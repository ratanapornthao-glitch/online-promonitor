# Methodology & Results

> ข้อมูลทั้งหมดเป็นข้อมูลสังเคราะห์ (synthetic) สำหรับสาธิตระบบ แบรนด์ สินค้า และราคาเป็นของสมมติ

## 1. Methodology: ขั้นตอนพัฒนาระบบ

| ขั้น | ทำอะไร | ทำไม |
| --- | --- | --- |
| 1. นิยามปัญหาและ schema | กำหนด 22 คอลัมน์ที่ต้องสกัดจากหน้าสินค้า (`CLAUDE.md`) โดยแยก `shop_voucher_thb` (แบรนด์ออก นับ) ออกจาก `platform_voucher_note` (แพลตฟอร์มออก ไม่นับ) | ตอบ pain point เรื่องส่วนลดซ้อนหลายชั้น และทำให้ทุกแพลตฟอร์มเทียบกันได้ |
| 2. สร้างชุดข้อมูลทดสอบที่รู้คำตอบ | `src/generate_synthetic.py` สร้าง screenshot จำลอง 420 ภาพ (5 แบรนด์ × 4 สินค้า × 3 แพลตฟอร์ม × 7 แคมเปญ) พร้อมค่าจริงทุกช่องใน `data/synthetic_truth.csv` และฝัง "เรื่องราว" ของคู่แข่ง 5 เรื่องไว้ล่วงหน้า | วัดความแม่นยำได้ 100% ของภาพ (ไม่ต้องกรอก ground truth เอง) และตรวจได้ว่าระบบหา insight ที่ถูกต้องเจอหรือไม่ |
| 3. ออกแบบ Agent | 3 subagent ใน `.claude/agents/`: extractor (Vision LLM → JSON), sku-matcher, analyst (Insight Agent) โดยมีกฎกลางใน `CLAUDE.md` เช่น "ห้ามเดาตัวเลข" | แยกหน้าที่ให้ตรวจสอบได้ทีละขั้น |
| 4. Validation | `src/validate.py` ใช้ Pydantic ตรวจชนิดข้อมูล ค่าที่อนุญาต และกฎธุรกิจ (ราคาขาย ≤ ราคาเต็ม, โค้ดร้าน ≤ ราคาขาย, ชื่อไฟล์ตรงกับภาพ) แล้วคำนวณ effective price / ราคาต่อหน่วย / % ส่วนลดใหม่เอง | ไม่ให้ตัวเลขจาก LLM เข้าระบบโดยไม่ผ่านการตรวจ |
| 5. Human-in-the-loop | แถวที่ confidence < 0.7 หรือมี flag เข้า `review_queue.csv` ให้คนตรวจก่อนวิเคราะห์ | OCR ภาษาไทยอาจผิด ตัวเลขผิดแย่กว่าไม่มีตัวเลข |
| 6. Analysis + Insight | `src/analyze.py` คำนวณ 10 ตาราง (Campaign Uplift, Promo Calendar, Channel Depth, Best Channel Share, Upsell Mix, Fake Discount ฯลฯ) แล้ว analyst agent เขียน brief ภาษาไทยจากตัวเลขในตารางเท่านั้น | ทุกตัวเลขใน insight ตรวจย้อนกลับได้ |
| 7. Evaluation | `src/evaluate.py` เทียบผลกับค่าจริงทีละช่อง (ยอมคลาด ±1 บาท) และบันทึกเวลาใน `run_log.csv` | วัดทั้งความแม่นยำและ Time to Insight |
| 8. Dashboard | `app.py` (Streamlit) อ่านเฉพาะไฟล์ผลลัพธ์ deploy แบบ public ที่ online-promonitor.streamlit.app | ไม่มี API key บนเว็บ ไม่มีค่าใช้จ่ายเมื่อเปิดดู |

## 2. การทดลอง: Blind test กับแคมเปญ `payday_2026-11`

**ตั้งค่า**
- Input: screenshot ใหม่ 60 ภาพ (Payday 25 พ.ย.) ที่ระบบไม่เคยเห็น
- รัน extractor 3 ตัวพร้อมกัน (แพลตฟอร์มละ 20 ภาพ) แต่ละตัวถูกสั่งให้อ่านจากภาพเท่านั้น และตรวจ log แล้วว่า**ไม่มีตัวไหนเปิดหรือรันคำสั่งกับไฟล์เฉลย**
- วัดความแม่นยำ **ก่อนคนตรวจ** (ความแม่นยำดิบของ Agent)
- เริ่มจับเวลาตอนสั่งรัน จบเมื่อได้ insight brief
- ทดลอง **2 รอบ** ด้วยค่าตัวเลขชุดเดียวกัน ต่างกันที่หน้าตาภาพ:

  | รอบ | วันที่ | หน้าตาภาพ |
  | --- | --- | --- |
  | 1 | 14 พ.ย. | หน้าสินค้าแบบเรียบ (กล่องชื่อแบรนด์แทนรูปสินค้า) |
  | 2 (ผลหลัก) | 16 พ.ย. | มี **รูปสินค้าวาด** (ขวด หลอด กระปุก) + ป้าย "ของแท้ 100%", "เซ็ตคู่สุดคุ้ม", "+ของแถม" บนรูป ใกล้หน้าจริงมากขึ้น |

  ผลด้านล่างเป็นของ **รอบ 2** ยกเว้นที่ระบุ

## 3. Results

### 3.1 ความแม่นยำในการสกัดข้อมูล (60 ภาพ, ก่อนคนตรวจ)

| ฟิลด์ | ถูก | ความแม่นยำ |
| --- | --- | --- |
| ราคาเต็ม (list_price) | 60/60 | 100% |
| ราคาขาย (display_price) | 60/60 | 100% |
| โค้ดร้าน (shop_voucher_thb) | 60/60 | 100% |
| **แยกส่วนลดแบรนด์/แพลตฟอร์ม** (brand net price) | 60/60 | 100% |
| ขนาด (size_ml_g) | 60/60 | 100% |
| กลไกอัพเซลล์ (upsell_mechanic) | 60/60 | 100% |
| ยอดขั้นต่ำ (min_spend_or_qty) | 60/60 | 100% |
| ชื่อสินค้า ภาษาไทยตรงทุกตัวอักษร | 60/60 | 100% |
| ของแถม / ข้อความโปร / voucher แพลตฟอร์ม | 60/60 | 100% |

- ทั้ง 2 รอบได้ 100% ทุกฟิลด์ (รอบ 1: confidence เฉลี่ย 0.93 / รอบ 2: 0.95 ต่ำสุด 0.90) ไม่มีแถวที่ต้องให้คนตรวจ
- จุดที่ Agent รายงานว่าไม่แน่ใจ:
  - "เซ็ตคู่สุดคุ้ม 2 ชิ้น ลดเพิ่ม 15%" ควรเป็น `bundle` หรือ `multi_buy` Agent เลือก `bundle` (ถูก) และลด confidence ลงเอง
  - รอบ 2: รูปสินค้าโชว์ **2 ขวด** แต่ชื่อและราคาเป็นของ 1 ชิ้น Agent ใช้ชื่อสินค้าและกล่องราคาเป็นหลัก ตั้ง `pack_qty` = 1 (ถูก) ไม่ถูกรูปหลอก ถ้าตั้งเป็น 2 ราคาต่อ ml จะผิดไปครึ่งหนึ่ง
- SKU matching: 60 รายการจับคู่ได้ 20 SKU ครบทั้ง 3 แพลตฟอร์ม

### 3.2 เวลา (Time to Insight)

| ขั้น | รอบ 1 | รอบ 2 (มีรูปสินค้า) |
| --- | --- | --- |
| อ่านภาพ 60 ภาพ (3 agent พร้อมกัน) | 1.4 นาที | 2.2 นาที |
| ตั้งแต่เริ่มจนได้ insight brief | 4.2 นาที | **4.6 นาที** (≈ 4.6 วินาที/ภาพ) |
| คนตรวจ | 0 นาที | 0 นาที (ไม่มีแถวติด flag) |
| ทำมือ (สมมติฐานจาก proposal: 2–3 วัน) | ~20 ชม. | ~20 ชม. |

*เวลาไม่รวมการแคปหน้าจอ ซึ่งยังเป็นงานของคน และตัวเลขทำมือเป็นค่าประมาณจาก pain point ไม่ได้จับเวลาจริง*

### 3.3 Insight ที่ระบบหาเจอ (เทียบกับเรื่องที่ฝังไว้)

| เรื่องที่ฝังในข้อมูล | ระบบพบหรือไม่ | หลักฐานจากตัวชี้วัด |
| --- | --- | --- |
| Nurish Lab อัดหนักช่วง Payday | ✅ | Uplift สูงสุด +23.8pp (Payday ต.ค. +21.9pp) สม่ำเสมอทั้ง 2 รอบ |
| Kiriya แทบไม่ลด | ✅ | Uplift +2.2pp ต่ำสุด |
| Vela Skin ทำ fake discount บน Lazada | ✅ | ราคาเต็ม 4 SKU สูงกว่าวันปกติ 18.1–18.6% |
| Lumira ดัน Shopee | ✅ | ส่วนลดเฉลี่ยทุกแคมเปญบน Shopee 41.7% สูงกว่าแพลตฟอร์มอื่น |
| Hadaso เน้น TikTok และ Flash Sale | ✅ | TikTok 47.1%, Uplift ช่วง Flash Sale +32.8pp |

## 4. ข้อจำกัดของผลลัพธ์ (ต้องพูดตรง ๆ)

- **ภาพจำลองอ่านง่ายกว่าของจริง:** แม้รอบ 2 จะมีรูปสินค้าและป้ายบนรูปแล้ว ตัวอักษรยังคมชัด layout เดียวกันทุกภาพ ไม่มี pop-up หรือแบนเนอร์ซ้อน ความแม่นยำ 100% จึงเป็น **ขอบบน** หน้าจริงของ Shopee/Lazada/TikTok คาดว่าจะต่ำกว่านี้ และเป็นเหตุผลที่ต้องมีขั้น Validation และคนตรวจ
- **ตัวอย่างที่ Validation ช่วยได้:** ในชุดข้อมูลเดิม (ผล extractor จำลองที่ใส่ข้อผิดพลาดไว้) Validation จับราคาที่อ่านผิดได้ 2 รายการ ซึ่ง extractor ไม่ได้ติด flag เอง
- **ชุดทดลองมีแคมเปญเดียว 60 ภาพ** ควรทดสอบเพิ่มกับ screenshot จริงจำนวนน้อยก่อนใช้งานจริง
- **GP ของคู่แข่งไม่ทราบ** คำอธิบายที่อิง GP เป็นสมมติฐาน
